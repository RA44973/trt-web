ОБНОВЛЕНИЕ 4P — МОБИЛЬНОЕ ПРИЛОЖЕНИЕ И ВЕБ-КАБИНЕТ

Что добавлено

1. Мобильное приложение
- В окне «Визит» появился блок оценки ТРТ по 4P.
- Place:
  • привлекательность расположения ТРТ — оценка 1–5;
  • размещение товара ВОГ внутри ТРТ — оценка 1–5.
- Product:
  • ввод общего количества SKU;
  • автоматическая оценка ассортимента:
    1 — менее 300;
    2 — 300–799;
    3 — 800–1499;
    4 — 1500–2999;
    5 — 3000 и более;
  • ввод доли ВОГ, %;
  • автоматическая оценка доли ВОГ:
    1 — до 5%;
    2 — 6–10%;
    3 — 11–19%;
    4 — 20–29%;
    5 — 30% и более;
  • признак наличия устаревших образцов.
- Promotion:
  • мотивация владельца — оценка 1–5;
  • мотивация продавцов / VOG Club — оценка 1–5;
  • качество бренд-зоны — оценка 1–5.
- Price отображается как «Нет данных / не оценивается».
- Итоговый рейтинг рассчитывается как среднее трёх оценок:
  Place, Product и Promotion.
- Все обязательные показатели должны быть заполнены перед сохранением визита.
- Последняя оценка 4P отображается в карточке ТРТ в МП.
- Оценка 4P отображается в истории визитов МП.

2. Сервер
- 4P передаётся вместе с визитом через существующие маршруты /visits/sync и /visits.
- Для совместимости с текущей YDB отдельная миграция таблиц не требуется.
- Существующие визиты без 4P продолжают работать.
- API Gateway менять не требуется.

3. Веб-кабинет
- В карточке ТРТ показывается последняя оценка 4P.
- В карточке визита показываются:
  • итоговый рейтинг;
  • Place, Product, Promotion;
  • все семь подоценок;
  • количество SKU;
  • доля ВОГ;
  • наличие устаревших образцов;
  • комментарий к 4P;
  • статус Price.
- Старые визиты без 4P отображаются без ошибок.

Порядок установки
1. Cloud Function: загрузить Cloud_Function_4P_визиты.zip в trt-api и создать версию.
2. Сайт: загрузить содержимое Сайт_4P_карточка_ТРТ.zip в корень trt-web.
3. МП: загрузить app.js и sw.js из МП_4P_в_визите.zip в корень trt-mobile.
4. После публикации полностью обновить сайт и МП.

Cloud Function
- Python 3.12
- точка входа index.handler
- таймаут, память, сервисный аккаунт и переменные окружения не менять.

Важно
Промежуточные границы Product (оценки 2–4) в этом варианте зафиксированы
по диапазонам, указанным выше. При необходимости их можно скорректировать
без изменения структуры данных.
