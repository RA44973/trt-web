РОЛЕВАЯ МОДЕЛЬ ДОСТУПА — ГД / КД / РРО / МЕНЕДЖЕР

Версия API: 2026-07-31-role-access-1
Версия модели доступа: 2026-07-31-roles-1
Версия МП: v2.8

Логика доступа

1. ГД
- все направления;
- все ТРТ, визиты, задачи, фото/видео, рейтинги 4P, продажи и сотрудники.

2. КД
- все материалы своего направления;
- подчинённость не ограничивает доступ КД.

3. РРО
- только своё направление;
- собственная клиентская база;
- клиентская база всех подчинённых по всей вложенной иерархии.
- сотрудники, подчинённые напрямую ГД или КД, в область РРО не входят.

4. Менеджер
- только собственная клиентская база;
- связанные ТРТ, визиты, задачи, материалы, 4P и продажи.

Что изменено

Cloud Function
- сервер фильтрует ТРТ, визиты, задачи, медиа и сотрудников;
- ограничения действуют на API, а не только на интерфейс;
- создание визита, задачи или материала возможно только в доступной ТРТ;
- в функцию добавлен файл employees_access.json;
- в защищённом справочнике каждой ТРТ добавлен managerEmployeeId.

Мобильное приложение
- получает с сервера только доступные пользователю ТРТ;
- очищает недоступные локальные данные при смене пользователя;
- удаляет из локального журнала записи, которые больше не входят в область доступа;
- офлайн-кэш принадлежит конкретному сотруднику;
- импорт общего справочника и восстановление общей копии доступны только ГД;
- в профиле показывается понятное название роли.

Сайт
- получает только отфильтрованные сервером данные;
- при выходе очищает данные предыдущей сессии;
- справочник сотрудников показывается в пределах роли;
- изменение структуры сотрудников через сайт временно отключено:
  источником является файл «Сотрудники».

Порядок установки

1. YDB — рекомендуется выполнить:
   01_Синхронизировать_профили_сотрудников.sql

   Этот SQL синхронизирует карточки и иерархию employee_profiles.
   Пароли и учётные записи он НЕ создаёт.

2. Cloud Function trt-api
- загрузить архив Cloud_Function_Ролевая_модель_доступа.zip;
- точка входа: index.handler;
- Python 3.12;
- память, таймаут, сервисный аккаунт и переменные окружения не менять;
- создать новую версию;
- проверить /health:
  api_version = 2026-07-31-role-access-1
  access_model_version = 2026-07-31-roles-1

3. Сайт
- загрузить всё содержимое архива Сайт_Ролевая_модель_доступа.zip
  в корень репозитория trt-web с заменой;
- дождаться публикации GitHub Pages;
- выполнить жёсткое обновление страницы.

4. Мобильное приложение
- загрузить app.js и sw.js из архива МП_v2.8_Ролевая_модель_доступа.zip
  в корень trt-mobile с заменой;
- дождаться публикации;
- полностью закрыть и снова открыть установленное МП.

API Gateway менять не требуется.
